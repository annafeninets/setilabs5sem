# lab3 — «Места»: асинхронное сетевое взаимодействие (C++)

Консольное приложение на C++20. Пользователь вводит название места («Цветной проезд»),
приложение находит варианты локаций, пользователь выбирает один из них, после чего
программа **одновременно** запрашивает погоду и интересные места рядом, затем для каждого
найденного места запрашивает описание и выводит всё **одним готовым отчётом**.

Все сетевые вызовы асинхронные: HTTP-клиент работает на libcurl multi interface в одном
фоновом потоке, а логика программы строится на собственных `Future` с продолжениями
(аналог `CompletableFuture`). Блокирующее ожидание (`get()`) есть только в консольном
интерфейсе и только на конечных результатах двух функций логики.

## Используемые API

| № | Назначение                              | API                                       | Где используется                  |
|---|------------------------------------------|---------------------------------------------|--------------------------------------|
| 1 | локации по названию (координаты, имена) | GraphHopper Geocoding `/api/1/geocode`      | `GraphHopperGeocoder`                |
| 1* | запасной геокодер (если GraphHopper недоступен) | OpenStreetMap Nominatim `/search`, ключ не нужен | `NominatimGeocoder`, `FallbackGeocoder` |
| 2 | погода по координатам                    | OpenWeatherMap `/data/2.5/weather`          | `OpenWeatherProvider`                |
| 3 | интересные места по координатам          | OpenTripMap `/0.1/ru/places/radius`         | `OpenTripMapCatalog::nearby`         |
| 4 | описание места по `xid`                  | OpenTripMap `/0.1/ru/places/xid/{xid}`      | `OpenTripMapCatalog::describe`       |

## Как устроена асинхронность

Логика программы — две функции класса `PlaceService`, каждая возвращает `Future` и не блокируется:

1. `findLocations(query)` — п. 2: поиск локаций (метод 1).
2. `buildReport(location)` — п. 4–5: погода и места с описаниями (методы 2, 3, 4), результат — один объект `Report`.

```
buildReport(location)
 ├── погода (метод 2) ───────────────────────────────┐
 └── места (метод 3) ─► описания (метод 4) × N ──────┴─► Report
        зависимая цепочка   N запросов параллельно
```

| Требование задания                                          | Как выполнено                                                                              |
|---------------------------------------------------------------|----------------------------------------------------------------------------------------------|
| асинхронная HTTP-библиотека                                   | `HttpClient`: libcurl multi interface, `get(url)` сразу возвращает `Future`                 |
| независимые вызовы одновременно                              | погода и поиск мест стартуют вместе; описания всех мест запрашиваются параллельно (`whenAll`) |
| зависимые вызовы — асинхронная цепочка                       | `nearby(...).then(описания мест).then(Report)` — без ожиданий внутри цепочки                |
| результаты собираются в общий объект, без поэтапного вывода  | `Report` выводится только после завершения всей работы                                      |
| блокировка только на конечном результате                     | `get()` вызывается лишь в `ConsoleApp` на результатах двух функций                          |
| устойчивость к сбоям                                          | ошибка погоды / списка мест / одного описания показывается в отчёте, остальное не теряется  |

## Почему именно такие API и ограничения

- **GraphHopper, OpenWeatherMap, OpenTripMap** — бесплатные ключи, ответы в JSON, обычный HTTPS GET; вместе
  дают всю цепочку «название → координаты → погода и места → описания».
- **Лимиты бесплатных ключей** учтены осознанно: показывается не более `kMaxPlaces = 5` мест, поэтому
  одновременно уходит не более 5 запросов описаний (иначе легко упереться в лимит OpenTripMap и получить `HTTP 429`).
- **Параллелизм обеспечивает libcurl multi**, а не пул потоков: один рабочий поток неблокирующе
  обслуживает все текущие запросы; ожидание событий — `curl_multi_poll`, добавление новых запросов будит
  его через `curl_multi_wakeup`.
- **Зависшая сеть**: каждый запрос ограничен `CURLOPT_TIMEOUT = 20 с` (соединение — 10 с), а ожидание
  конечного результата в `ConsoleApp` ограничено 120 с (`Future::get(timeout)`) — программа не повиснет навсегда.
- **Известное ограничение**: некоторые API отвечают ошибкой в теле с кодом 200; проверяется только поле
  `"error"` (строка) верхнего уровня, остальные нестандартные ответы дадут пустые данные
  («Ничего не найдено» / «места недоступны»).

## Обработка ошибок

| Ситуация                                  | Поведение                                                                              |
|---------------------------------------------|--------------------------------------------------------------------------------------------|
| сбой погоды или списка мест               | `Outcome<T>` хранит текст ошибки; отчёт строится, на месте раздела — «недоступна (...)»   |
| сбой одного описания места                | `recover` подставляет место без описания (`(описание не удалось загрузить)`)              |
| сброс соединения / таймаут при запросе    | `RetryingHttpClient` автоматически повторяет запрос (до 2 раз)                            |
| GraphHopper недоступен                    | `FallbackGeocoder` ищет локации через Nominatim (OpenStreetMap, без ключа)                |
| сбой поиска локаций / сеть недоступна     | исключение из `get()`, `ConsoleApp` печатает `Ошибка: ...` и ждёт новый ввод              |
| ответ не уложился в 120 с                  | `TimeoutError` -> `Ошибка: timed out waiting for result`                                    |

## Сборка и запуск в Windows (CLion)

Приложение — обычная консольная программа-клиент: ей нужен только интернет. **Виртуальные машины
и несколько компьютеров не нужны** (в примере с передачей файла они требовались, чтобы запустить
сервер и клиентов на разных машинах; здесь всё взаимодействие идёт с публичными API). Запускать
можно прямо из CLion или из терминала — результат одинаковый.

### 1. Установка зависимостей (один раз)

Нужны библиотеки libcurl и nlohmann-json. Их ставит vcpkg (в PowerShell):

```powershell
git clone https://github.com/microsoft/vcpkg C:\vcpkg
C:\vcpkg\bootstrap-vcpkg.bat
```

В проекте есть файл `vcpkg.json`, поэтому при загрузке CMake vcpkg **сам скачает и соберёт**
curl и nlohmann-json (в первый раз это занимает несколько минут — смотрите вкладку *CMake* в CLion;
прогресс виден в её выводе). Ставить библиотеки вручную не нужно.

Параметры CMake зависят от компилятора, выбранного в CLion
(*Settings → Build, Execution, Deployment → Toolchains*):

| Toolchain в CLion          | Параметры CMake (поле *CMake options*)                                                                          |
|-----------------------------|----------------------------------------------------------------------------------------------------------------------|
| Visual Studio (MSVC)        | `-DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake`                                                   |
| MinGW (встроенный в CLion)  | `-DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-mingw-static -DVCPKG_HOST_TRIPLET=x64-mingw-static` |

Для MSVC в *Toolchains* должна быть архитектура **amd64** (не x86).

### 2. Запуск из CLion

1. *File → Open* → выбрать папку проекта `lab3_cpp`.
2. *Settings → Build, Execution, Deployment → CMake* → в поле **CMake options** вставить параметры
   из таблицы выше → OK (CLion перезагрузит CMake; при первой загрузке vcpkg может собирать
   библиотеки несколько минут).
3. В правом верхнем углу выбрать конфигурацию `lab3_places` → *Edit Configurations…* →
   в поле **Working directory** указать папку проекта (где лежит `.env`).
4. Нажать *Run* (Shift+F10). В окне *Run* появится приглашение `Введите название места (или exit):`.

### 3. Запуск из терминала (альтернатива)

В PowerShell в папке проекта (подставьте нужный вариант параметров из таблицы):

```powershell
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake
cmake --build build --config Release
```
Запуск (из папки проекта):
```powershell
.\build\Release\lab3_places.exe     # MSVC
.\build\lab3_places.exe             # MinGW
```

### Linux / macOS

```bash
sudo apt install g++ cmake libcurl4-openssl-dev nlohmann-json3-dev   # macOS: brew install cmake curl nlohmann-json
cmake -S . -B build && cmake --build build
./build/lab3_places
```

## Настройка ключей

Ключи читаются из файла `.env` (он уже лежит в корне проекта; при сборке копируется и рядом с
исполняемым файлом) или из переменных окружения (они приоритетнее):

```
API_KEY_GRAPHHOPPER=...
API_KEY_OPENWEATHER=...
API_KEY_OPENTRIPMAP=...
```

Ключ OpenWeatherMap после регистрации может активироваться до пары часов — до этого погода
вернёт `HTTP 401`, это отобразится в отчёте строкой «недоступна (...)».

## Как протестировать работу с интернетом

Запустите программу (подключение к интернету должно быть включено) и проверьте сценарии:

| № | Что сделать                                         | Что должно произойти                                                                                              |
|---|--------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------|
| 1 | ввести `Цветной проезд`, выбрать номер `1`            | список локаций с координатами; затем отчёт: погода + до 5 интересных мест с описаниями; в конце `(готово за N с)`   |
| 2 | ввести `Красная площадь` / `Эрмитаж`, выбрать любой номер | то же для другого места; у большинства известных мест есть описания из Википедии                                  |
| 3 | на сценарии 1 посмотреть время `готово за`           | порядка 1–3 с, т.е. примерно время самых долгих запросов цепочки (места → описания), а **не сумма** 7 запросов — это подтверждает параллельность |
| 4 | ввести бессмысленную строку `qwertyuiop123`           | «Ничего не найдено.» (либо список случайных совпадений); программа продолжает работать                             |
| 5 | на запрос номера ввести `abc` или `99`                | «Неверный номер.», возвращение к вводу названия                                                                    |
| 6 | в `.env` испортить ключ погоды (`API_KEY_OPENWEATHER=xxx`) и повторить сценарий 1 | погода: `недоступна (OpenWeather: HTTP 401 ...)`, а места и описания всё равно выведены (сбой одного API не ломает остальное) |
| 7 | испортить ключ OpenTripMap                            | места: `недоступны (OpenTripMap: HTTP 401 ...)`, погода выведена                                                   |
| 8 | отключить интернет (Wi-Fi/кабель) и повторить          | `Ошибка: network error: ...` — программа не зависает и не падает, можно повторить ввод после подключения          |
| 9 | ввести `exit`                                         | программа завершается                                                                                              |

Дополнительно параллельность можно показать так: сравнить время сценария 1 со временем в
браузере, выполняя те же запросы по очереди (суммарно будет заметно дольше).

### Если что-то не работает

| Симптом                                                     | Причина и решение                                                                                     |
|----------------------------------------------------------------|------------------------------------------------------------------------------------------------------------|
| `Предупреждение: не заданы API-ключи`                         | не найден `.env`: проверьте *Working directory* в конфигурации запуска (см. п. 2.3) или задайте переменные окружения |
| CMake: `Could NOT find CURL`                                  | в vcpkg не установлена libcurl для нужного triplet. Убедитесь, что в проекте есть `vcpkg.json`, удалите папку `cmake-build-debug` и выполните *Tools → CMake → Reset Cache and Reload Project*. Вручную: `C:\vcpkg\vcpkg install curl:x64-windows nlohmann-json:x64-windows` (для MinGW — `x64-mingw-static`) |
| русские буквы отображаются как `???`                          | в терминале выполнить `chcp 65001`; в окне *Run* CLion кодировка обычно UTF-8 (*Settings → Editor → File Encodings*) |
| `Ошибка: network error: ... SSL ...`                          | проверьте системные дату/время и корпоративный прокси/антивирус, перехватывающий HTTPS                    |
| `HTTP 429`                                                    | превышен лимит запросов бесплатного ключа; подождите минуту и повторите                                   |
| погода: `HTTP 401`                                            | ключ OpenWeatherMap ещё не активирован либо введён неверно                                                |
