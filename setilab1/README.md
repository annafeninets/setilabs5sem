# setilab1 — обнаружение копий себя в локальной сети

Приложение обнаруживает другие запущенные копии себя в локальной сети с помощью
обмена UDP multicast-сообщениями. При появлении или исчезновении
копии выводится актуальный список IP-адресов "живых" копий.

Адрес multicast-группы передаётся параметром командной строки. Семейство
протокола (**IPv4** или **IPv6**) определяется автоматически по формату адреса
— оба протокола поддержаны и проверены на практике (см. раздел «Тестирование»).

## Структура проекта

```
setilab1/
├── include/
│   ├── Constants.h            # все константы (порт, тайминги, имя сообщения, интерфейс)
│   ├── Multicast address.h    # парсинг и валидация адреса группы (IPv4/IPv6)
│   ├── Multicast sender.h     # отправка heartbeat-сообщений
│   ├── Multicast receiver.h   # приём сообщений, членство в multicast-группе
│   ├── Peer tracker.h         # учёт живых копий и их TTL
│   └── Application.h          # связывает Sender/Receiver/Tracker в цикл обнаружения
├── src/
│   ├── main.cpp                # точка входа: разбор аргументов, запуск Application
│   ├── Multicast address.cpp
│   ├── Multicast sender.cpp
│   ├── Multicast receiver.cpp
│   ├── Peer tracker.cpp
│   └── Application.cpp
├── CMakeLists.txt
├── Dockerfile
└── docker-compose.yml
```

## Сборка

### CMake (CLion или консоль)

```bash
cmake -S . -B cmake-build-debug
cmake --build cmake-build-debug
```
Исполняемый файл — `cmake-build-debug/setilab1`.

### Вручную через g++

```bash
g++ -std=c++20 -Wall -Wextra -O2 \
    -Iinclude \
    src/main.cpp "src/Multicast address.cpp" "src/Multicast sender.cpp" \
    "src/Multicast receiver.cpp" "src/Peer tracker.cpp" src/Application.cpp \
    -o setilab1
```

## Запуск

```bash
./setilab1 <multicast-адрес>
```

Примеры:
```bash
./setilab1 239.255.0.1     # IPv4
./setilab1 ff02::1         # IPv6 (link-local)
```

Каждая запущенная копия раз в секунду рассылает heartbeat в группу и слушает
сообщения от остальных. Если копия не подавала признаков жизни дольше 2 секунд,
она считается "умершей" и удаляется из списка. При любом изменении список
живых копий печатается заново:

```
Живых копий: 3
  192.168.100.10 : 41231
  192.168.100.11 : 55012
  192.168.100.12 : 60870
```

## Константы (`include/Constants.h`)

| Константа            | Значение      | Назначение                                   |
|-----------------------|---------------|-----------------------------------------------|
| `PORT`                | 8080          | UDP-порт обмена                               |
| `HEARTBEAT_MS`        | 1000          | период отправки собственного heartbeat        |
| `TTL_MS`              | 2000          | время жизни записи о копии без новых пакетов   |
| `RECV_TIMEOUT_US`     | 200000        | таймаут ожидания на приём (recvfrom)           |
| `MESSAGE`             | `"tosi bosi"` | содержимое heartbeat, по которому узнают копии |
| `NETWORK_INTERFACE`   | `enp0s3`      | интерфейс, используемый для IPv6 scope_id      |

## Тестирование на трёх виртуальных машинах (Oracle VirtualBox)

Приложение проверялось на трёх клонированных Ubuntu-VM, объединённых
внутренней сетью VirtualBox (`Internal Network`, имя `lab-net`) плюс
отдельный NAT-адаптер для доступа в интернет и проброшенный SSH-порт с хоста.

| VM   | IP              | SSH-порт (host) | Multicast-маршрут через `enp0s3` |
|------|-----------------|------------------|-----------------------------------|
| vm1  | 192.168.100.10  | 2222             | `224.0.0.0/4` и `ff00::/8`         |
| vm2  | 192.168.100.11  | 2223             | то же                              |
| vm3  | 192.168.100.12  | 2224             | то же                              |

Перед запуском на **каждой** VM добавляются маршруты для multicast-трафика
(сбрасываются при перезагрузке — нужно добавлять заново):

```bash
sudo ip route add 224.0.0.0/4 dev enp0s3
sudo ip -6 route add ff00::/8 dev enp0s3
```

Запуск (в отдельном SSH-окне на каждой VM):

```bash
./setilab1 239.255.0.1     # или ff02::1 для проверки IPv6
```

Через 1–2 секунды на всех трёх VM в терминале появляется одинаковый список
из трёх адресов. Если остановить приложение (или выключить VM) на одной из
них, через ~2 секунды (TTL) оставшиеся копии обновляют список до двух
записей; при повторном запуске копия возвращается в список автоматически.

Так были независимо проверены оба сценария:
- **IPv4** — группа `239.255.0.1`;
- **IPv6** — группа `ff02::1` (link-local multicast, тот же `enp0s3`).

## Docker-окружение

В репозитории также есть `Dockerfile` и `docker-compose.yml`, поднимающие три
контейнера (`mcast-node1..3`) в общей bridge-сети `172.28.0.0/24` как более
лёгкую альтернативу трём VM, но работа производится только с адресами IPv4.

```bash
docker build -t setilab1 .
docker run --rm -it --name lab1-node setilab1


```
