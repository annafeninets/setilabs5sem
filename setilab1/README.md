# setilab1 — обнаружение копий себя в локальной сети

Приложение обнаруживает **другие** запущенные копии себя в локальной сети с помощью
обмена UDP multicast-сообщениями (heartbeat). При появлении или исчезновении
копии выводится актуальный список IP-адресов "живых" копий.

Адрес multicast-группы передаётся параметром командной строки. Семейство
протокола (**IPv4** или **IPv6**) определяется автоматически по формату адреса —
оба протокола проверены на практике (см. «Тестирование»).

## Как это работает

- Каждая копия при старте генерирует случайный **id экземпляра** (16 hex-символов).
- Раз в секунду она отправляет в группу heartbeat `tosi bosi|<id>`.
- Все копии слушают группу. Пакеты с чужим форматом отбрасываются,
  **собственные heartbeat (тот же id, приходят через multicast loopback) игнорируются**.
- Копия, от которой не было heartbeat дольше TTL (2 с), удаляется из списка.
- При любом изменении списка он печатается заново.
- Для IPv6 отправитель и получатель используют **один и тот же интерфейс**
  (`config::NETWORK_INTERFACE`): получатель вступает в группу на нём, отправитель
  задаёт его как исходящий (`IPV6_MULTICAST_IF` и `scope_id`).

## Структура проекта

```
setilab1/
├── include/
│   ├── constants.h            # все константы (порт, тайминги, интерфейс, формат сообщения)
│   ├── multicast_address.h    # парсинг/валидация адреса группы, IPv4/IPv6
│   ├── multicast_sender.h     # отправка датаграмм в группу
│   ├── multicast_receiver.h   # приём датаграмм, членство в группе
│   ├── udp_socket.h           # RAII-обёртка сокета (закрывается в деструкторе)
│   ├── network_interface.h    # имя интерфейса -> индекс
│   ├── instance_id.h          # генерация уникального id экземпляра
│   ├── heartbeat.h            # формат heartbeat (encode/decode)
│   ├── peer_tracker.h         # учёт живых копий и их TTL
│   ├── time_utils.h           # elapsedMs
│   └── application.h          # основной цикл: отправка, приём, фильтрация, учёт
├── src/                       # реализации (*.cpp с теми же именами) и main.cpp
├── CMakeLists.txt
├── Dockerfile
└── docker-compose.yml
```

Весь код находится в пространстве имён `setilab1`, константы — в `config`.

## Сборка

### CMake (CLion или консоль)

```bash
cmake -S . -B cmake-build-debug
cmake --build cmake-build-debug
```
Исполняемый файл — `cmake-build-debug/setilab1`.

### Вручную через g++

```bash
g++ -std=c++20 -Wall -Wextra -O2 -Iinclude src/*.cpp -o setilab1
```

## Запуск

```bash
./setilab1 <multicast-адрес>
```

Примеры:
```bash
./setilab1 239.255.0.1     # IPv4
./setilab1 ff02::1         # IPv6 (link-local); нужен интерфейс из constants.h
```

Пример вывода на одной из трёх машин:

```
Слушаю multicast-группу 239.255.0.1 (IPv4), порт 8080, id этой копии: 5e88bfc0ad8f78b6...
Живых копий (кроме этой): 2
  192.168.100.11  (id cdb2f49ed06cf221)
  192.168.100.12  (id 7af2aadbab9fc360)
```

Если интерфейс `enp0s3` не существует, запуск с IPv6-группой завершится ошибкой
`Сетевой интерфейс не найден` — измените `NETWORK_INTERFACE` в `include/constants.h`.

## Константы (`include/constants.h`)

| Константа             | Значение      | Назначение                                        |
|-----------------------|---------------|---------------------------------------------------|
| `PORT`                | 8080          | UDP-порт обмена                                   |
| `NETWORK_INTERFACE`   | `enp0s3`      | интерфейс для IPv6 (и отправка, и приём)          |
| `HEARTBEAT_MS`        | 1000          | период отправки heartbeat                         |
| `TTL_MS`              | 2000          | время жизни записи о копии без новых heartbeat    |
| `RECV_TIMEOUT_US`     | 200000        | таймаут ожидания на recvfrom                      |
| `MESSAGE`             | `"tosi bosi"` | префикс heartbeat-сообщения                       |
| `HEARTBEAT_SEPARATOR` | `'\|'`        | разделитель префикса и id                         |
| `MAX_DATAGRAM_SIZE`   | 256           | размер буфера приёма                              |

## Тестирование на трёх виртуальных машинах (Oracle VirtualBox)

Проверялось на трёх клонированных Ubuntu-VM в внутренней сети VirtualBox
(`Internal Network`, `lab-net`) + NAT-адаптер для доступа наружу и проброшенные SSH-порты.

| VM  | IP              | SSH-порт (host) |
|-----|-----------------|-----------------|
| vm1 | 192.168.100.10  | 2222            |
| vm2 | 192.168.100.11  | 2223            |
| vm3 | 192.168.100.12  | 2224            |

На **каждой** VM перед запуском (сбрасывается после перезагрузки):

```bash
sudo ip route add 224.0.0.0/4 dev enp0s3
sudo ip -6 route add ff00::/8 dev enp0s3
```

Запуск на каждой VM: `./setilab1 239.255.0.1` (IPv4) или `./setilab1 ff02::1` (IPv6).
Каждая копия показывает **две другие**. Если остановить одну — через ~2 секунды
(TTL) у остальных список сокращается до одной; при повторном запуске копия
возвращается в список.

## Docker

`docker-compose.yml` поднимает три контейнера в bridge-сети `172.28.0.0/24`
(только IPv4), по умолчанию с группой `239.255.0.1`:

```bash
docker compose up --build
```

IPv6-группа в этой сети не поддерживается (нет IPv6 в compose-сети и интерфейса
`enp0s3` в контейнере) — IPv6 проверяется на VM.
